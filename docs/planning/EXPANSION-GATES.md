# Expansion gates

25 October 2026. Global infrastructure is the direction; permitted access, payment paths and rights still require market-specific evidence. Google Cloud work is paused.

| Possible expansion | Evidence required before implementation/spend | Present promise |
| --- | --- | --- |
| Cross-chain bridge | Actual customer need, working supported source/destination, relayer owner, adversarial verification and separate approved budget | No hosted production bridge |
| Pools | Supported deployed runtime/pool, verified account path and funded bounded browser test | Availability depends on runtime; no fabricated liquidity |
| Automatic renewal | Retention monitoring, explicit operator authority, separate service balance and dry-run recovery | Manual approved transactions only |
| Automatic slashing | Reviewed incentives, timing/finality handling, responsible keeper and operating budget | Eligible users initiate existing Core actions |
| Compounding | Clear customer mandate and supported mechanism, verified accounting and independent review | No automatic reinvestment |
| Complete archive | Proven coverage/cursor recovery, durable source and restoration drill, cost owner | Published receipts are partial even when known totals match |
| Node tooling | Demonstrated operator need or separately evidenced award fit, maintenance owner and measured costs | No node hosting commitment |
| Real-money controlled funding | Operator evidence, qualified rights/custody review, independent contract review, release/refund design and approved migration budget | Core v1 sends net purchases to operator; no spending escrow |

Do not add infrastructure or deploy bytecode merely to name another award. Prioritize working operator evidence, understandable costs, recovery and verified browser use. Revisit each gate after POR-B08's customer-based continue/adjust decision; this document does not make that decision in advance.
